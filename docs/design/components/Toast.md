# Toast

Toast-уведомление с очередью, иконкой и необязательным действием.

- Левая кромка 3px и иконка по тону; успех/инфо — `role=status`, ошибки — `role=alert` и не исчезают сами.
- Очередь снизу справа (desktop) / сверху (mobile), максимум 3 одновременно.

## Уточнения владельца (2026-11-23, UI-2)

Где макет `Toast.html` расходится с контрактом (`api-contracts.d.ts`), прав контракт.

1. **Роль по тону:** info и success — `role=status`; warning и error — `role=alert`.
   В макете у warning стоит `role=status` — это ошибка макета.
2. **Иконка по тону — как у Alert** (у каждого тона своя форма): info → `info`,
   success → `circle-check`, warning → `triangle-alert`, error → `circle-alert`.
   В макете у error треугольник, как у warning, — ошибка макета.
3. **Крестик у каждого тоста** (`k-icon-btn`, имя из `KonturIntl.closeLabel`). В макете
   он есть только у success, но warning и error не исчезают сами — без крестика их не
   закрыть.
4. **Тост с действием (`action`) не исчезает сам**, даже info или success: за 5 секунд
   до кнопки не успеть с клавиатуры или скринридером (WCAG 2.2.1).
5. **Таймер останавливается**, пока на тосте курсор или фокус (WCAG 2.2.1).
6. **Mobile — ширина окна меньше 960 px** (единственный брейкпоинт системы, см.
   README): очередь сверху.
7. **Live-области создаются при старте приложения** (`provideKonturToast()`), а не вместе
   с первым сообщением: область, вставленная вместе с текстом, часто не озвучивается.
8. Тост никогда не забирает фокус. Если пользователь вошёл в тост клавишей Tab и закрыл
   его, фокус возвращается туда, где был до входа.
