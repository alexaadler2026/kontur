Версия 2 от 15.11.2026, решения владельца (Александр) внесены. Документ описывает, **что делает продукт и по каким правилам**, а не как это запрограммировано. Из него исходят ADR, API и тесты. Чего здесь нет — не придумывать, а спрашивать.

## 0. Продукт и запуск (общее для обоих приложений)

- **Это реальный продукт**, а не только портфолио. Владелец пользуется им в работе. Реальное использование — **в Кыргызстане**. Немецкий рынок — для демо и портфолио.
- **Две установки из одного кода:**

|         | Демо (для рекрутера и всех желающих)                        | Рабочая (реальное использование)      |
| ------- | ----------------------------------------------------------- | ------------------------------------- |
| Вход    | Готовый демо-аккаунт, логин и пароль на странице демо       | Регистрация **только по приглашению** |
| Данные  | Вымышленные, сбрасываются регулярно (например, каждую ночь) | Настоящие                             |
| Письма  | Наружу не уходят (тестовый почтовый ящик)                   | Реальная отправка                     |
| Хостинг | Бесплатный [открыто: какой]                                 | Сервер владельца в Нидерландах        |

- **Аккаунты:** свои (собственная регистрация), учётные записи SignFlow и Belegscan **раздельные**. Внешний провайдер входа (Keycloak и т. п.) — отдельный будущий ADR.
- **Безопасность:** документы и фото хранятся **зашифрованными**. Резервные копии. Защита от злоупотребления отправкой писем: только приглашённые пользователи могут отправлять.
- **Языки интерфейса:** de (по умолчанию), en, ru. [открыто: нужен ли кыргызский (ky) для реального использования]. Архитектура должна позволять добавить язык без переделки.

## SignFlow — электронное подписание документов

### Зачем

**Главный сценарий — подписать документ самому:** счёт на оплату, договор, акт. Потом при необходимости отправить его на подпись другим. Полный процесс «несколько подписантов» — второй сценарий той же v1. Аналоги: DocuSign, Adobe Sign, Skribble.

### Роли

| Роль                        | Кто это                                            | Что делает                                                                                   |
| --------------------------- | -------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| Отправитель (Absender)      | Пользователь с аккаунтом [М: Max Beispiel]         | Загружает, подписывает сам, отправляет, следит, напоминает, отменяет, продлевает срок        |
| Подписант (Unterzeichnende) | Любой человек с e-mail, **без аккаунта**           | Открывает ссылку из письма, подтверждает личность кодом из e-mail, подписывает или отклоняет |
| Проверяющий (Prüfer)        | Человек с e-mail, например юрист, **без аккаунта** | Проверяет документ **до** подписантов: подтверждает или возвращает с замечанием              |
| Администратор               | [М: «Verwaltung»]                                  | Пользователи и приглашения. Шаблоны (Vorlagen) — v2+                                         |

**Обязательно:** отправитель может быть и подписантом своего документа [М].

### Что хранится

- **Документ (Umlauf):** PDF-оригинал, название, контрагент (Vertragspartner), тип, сумма договора (Auftragswert) с валютой, срок (Frist), сообщение, дата отправки [М].
- **Отпечаток SHA-256 оригинала** [М].
- **Подписанты и проверяющие:** имя, e-mail, порядок, **язык писем** (по умолчанию — язык подписанта, отправитель может выбрать другой: de, en, ru).
- **Поля на страницах:** подпись, дата, имя, инициалы, **печать**; каждое привязано к человеку и месту [М + печать].
- **Профиль пользователя:** сохранённая **подпись** (нарисованная или загруженная) и **несколько печатей** с названиями (например, «CBI», «Дед Мороз — для новогодних поздравлений»). Пользователь выбирает печать при подписании.
- **Протокол (Protokoll):** время, человек, событие, IP. Экспорт CSV [М].

### Хранение и удаление

- Файлы хранятся **зашифрованными**.
- Документ можно **удалить**. При удалении PDF стираются, а в протоколе остаются: отпечаток SHA-256, кто, что и когда подписал. Так факт подписи можно доказать и без файла.
- **Срок хранения** в настройках: например, «удалять подписанные через N месяцев». Интерфейс предупреждает, что бухгалтерские документы по закону могут требовать хранения.

### Статусы документа

```
Entwurf ──▶ [In Prüfung] ──▶ Wartet (im Umlauf) ──все подписали──▶ Signiert ──▶ Archiv
  (необязательный этап)          │
                                 ├── подписант отклонил ──▶ Abgelehnt (останавливает документ для всех)
                                 ├── проверяющий вернул ──▶ Entwurf (с замечанием)
                                 └── отправитель отменил ──▶ Storniert
```

- **«Überfällig» — признак, а не статус:** «Wartet + срок прошёл». Вычисляется, не хранится. После **продления срока** признак исчезает, подписание снова возможно.
- **«In Prüfung»** — включается галочкой «Сначала проверка» на документе (v1). Конструктор этапов бизнес-процессов — **v2+**.
- Счётчик «2/3» — сколько подписантов подписали [М].

### Процесс 0. Быстро подписать самому (главный, v1)

1. Загрузить PDF → SHA-256 → протокол.
2. Поставить свою подпись и, при желании, печать из профиля.
3. Готово: скачать подписанный PDF **или** «Отправить на подпись другим» → процесс 1 с уже подписанным документом.

### Процесс 1. Подготовить и отправить (Neuer Umlauf)

1. Загрузить PDF (или продолжить из процесса 0).
2. Добавить подписантов (имя, e-mail, язык, порядок). При желании — галочка «Сначала проверка» и проверяющие.
3. Порядок: **последовательно** или **параллельно** [М]. При последовательном порядке письмо получает только текущий подписант.
4. Поля на страницах. **У каждого подписанта минимум одно поле подписи** [М].
5. Срок и сообщение [М]. Черновик сохраняется автоматически [М].
6. «Senden» → «In Prüfung» или «Wartet».

### Процесс 2. Подписать (Signieren)

1. Ссылка из письма **действует ограниченное время** (до срока документа или N дней). Сама ссылка не одноразовая: корпоративная почта и антивирусы открывают ссылки для проверки и «сожгли» бы её.
2. При каждом входе — **одноразовый код из e-mail** [М: «Identität per E-Mail-Code bestätigt»].
3. Проход по своим полям [М]. Подпись: нарисовать, напечатать, загрузить [М]. Печать — если поле печати назначено.
4. Согласие с простой электронной подписью [М: текст eIDAS SES]. [открыто: юридический текст для Кыргызстана — см. вопросы для архитектуры].
5. Или **отклонить с причиной** → «Abgelehnt», документ останавливается для всех.
6. Каждое действие — в протокол с IP [М].

### Процесс 3. Сопровождение

- **Напоминание:** в v1 только вручную, кнопкой «Erinnern» [М]. Автоматические — v2+.
- **Просрочка:** признак «Überfällig» [М]. Отправитель может **продлить срок** — документ снова доступен для подписи.
- **Массовые действия:** напомнить, скачать, отменить [М].
- **Обзор:** «ждут моей подписи», «ждут других», «просрочено», последние события [М].

### Процесс 4. Завершение

- Все подписали → «Signiert» [М].
- **Итоговый PDF:** подписи и печати вставлены в поля плюс последняя страница с протоколом. Хранится вместе с оригиналом.
- Проверка целостности по отпечатку [М].

### Уровень подписи

- v1 — только **простая электронная подпись** (SES).
- AES и QES — в интерфейсе как **неактивный вариант с пометкой «geplant»**. Не обещать то, чего нет.

### v2+ (SignFlow)

Конструктор этапов бизнес-процессов; автоматические напоминания; шаблоны (Vorlagen); AES/QES; несколько организаций; мобильное приложение.

## Belegscan — чеки и счета: снять, распознать, проверить, учесть

### Зачем

Пользователь фотографирует чеки или загружает их пачкой. Приложение распознаёт магазин, дату, позиции, налоги и сумму, помогает проверить сомнительное, показывает расходы и выгружает данные для бухгалтерии.

### Пользователи и группы (v1 — простой вариант)

- Пользователь состоит в **группе** (например, компания).
- Все участники группы видят чеки группы. **Роль «бухгалтер»** подтверждает чеки (статус «Bestätigt»).
- Сложные маршруты согласования (сотрудник → бухгалтер → главный бухгалтер) — v2+.

### Страны, валюты, налоги

- **Германия — полная поддержка в v1:** НДС 7 % и 19 %, проверка TSE-QR [М].
- **Другие страны (Кыргызстан, Россия и др.):** любая валюта и **ставка налога вручную**. Специальные проверки (например, фискальный QR налоговой службы) — v2+.
- **Каждая сумма хранится с кодом валюты** (EUR, KGS, RUB…). Суммы — **точно, без округления**:
  - суммы чека — целым числом в минимальных единицах валюты (центы, тыйыны, копейки): 15,86 € = 1586;
  - цены за единицу (например, топливо 1,789 €/л) — точной десятичной строкой;
  - никаких чисел с плавающей точкой для денег.

### Что хранится

- **Чек (Beleg):** магазин, дата, способ оплаты, позиции (товар, количество, ставка налога, сумма), суммы налога по ставкам, итог, **валюта**, категория, **фото (это и есть сам документ, хранится зашифрованным)**, статус [М].
- **Уверенность распознавания** по каждому полю: ≥ 85 % «sicher», 60–85 % «prüfen», < 60 % «unsicher» [М].
- **Проверки:** сумма позиций = итог [М]; TSE-QR (только Германия) [М].
- **Пакет (Stapel)** и статусы файлов [М].

### Статусы чека

```
Warteschlange ──▶ Erkannt (всё уверенно) ──┐
              └─▶ Zu prüfen (есть сомнения) ┴──человек подтвердил──▶ Bestätigt
Плюс: Nicht lesbar (снять заново / ввести вручную), Duplikat (пропущен, можно «Behalten»)
```

- **«Bestätigt» («Принят»)** — отдельный статус: человек проверил и подтвердил.
- **Автоподтверждение** — настройка, **по умолчанию выключена**. Срабатывает, только если одновременно: все поля выше порога, сумма позиций = итог, TSE совпал (где применимо). Такие чеки помечены «подтверждён автоматически».
- Ошибки проверки (суммы не сходятся и т. п.) показываются **уведомлением** и на самом поле.

### Процесс 1. Снять один чек

1. Камера с рамкой [М] → обрезка и перспектива [М].
2. **Распознавание в браузере (ONNX)** [М] → редактор с подсветкой уверенности [М].
3. Проверки суммы и TSE; «Differenz als Position» [М].
4. Сохранить, подтвердить или отбросить. Не читается → снять заново, из галереи, вручную [М].

### Процесс 2. Пакетная загрузка (Stapel-Import)

1. JPG, PNG, HEIC, PDF, ZIP; максимум 200 файлов и 250 МБ [М]. **ZIP распаковывается в браузере**, потоково.
2. Распознавание по одному файлу, локально; пауза и отмена [М].
3. Опции: пропуск дубликатов (магазин + дата + сумма), автоподтверждение (см. условия выше), общая категория [М].
4. Сводка [М].

### Процесс 3. Электронные счета (v1)

- PDF-счета с встроенными данными **ZUGFeRD / XRechnung**: данные читаются из XML внутри PDF, без распознавания. Точно и сразу.
- Распознавание произвольных многостраничных счетов — v2+.

### Процесс 4. Проверка на компьютере (Prüfwarteschlange) [М]

### Процесс 5. Список, аналитика, экспорт

- Список по месяцам; свайп — поделиться или удалить [М]. Аналитика [М] — **суммы по валютам раздельно**, без смешивания.
- **Экспорт v1: универсальный CSV** (поля чека, позиции, налоги, валюта). Его можно загрузить и в 1С через обработку.
- Настоящий формат DATEV (Buchungsstapel, план счетов SKR03/04) и адаптер 1С — v2+.

### Офлайн и синхронизация

- Распознавание работает без сети (в браузере). Без сети ждёт **синхронизация**: данные и фото уходят на сервер, когда появится связь.
- Текст баннера уточнить: «Offline — der Beleg wird synchronisiert, sobald Verbindung besteht».

### v2+ (Belegscan)

Маршруты согласования в группе; фискальные QR других стран; DATEV Buchungsstapel; адаптер 1С; распознавание многостраничных счетов; отправка бухгалтеру напрямую; банковские выписки.
