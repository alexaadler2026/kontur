## UI-4 · SideNav в libs/ui (без зависимости от роутера)

`libs/ui` не знает о роутере: ссылки и активность задаёт приложение (`routerLink`,
`routerLinkActive` с `ariaCurrentWhenActive="page"`), а компонент только оформляет их по
`[aria-current]`. Так он подходит и Belegscan, и Storybook.

| Часть               | Что это                                                               | Доступность                                 |
| ------------------- | --------------------------------------------------------------------- | ------------------------------------------- |
| `<k-sidenav>`       | `<nav>` с обязательным `aria-label`; слоты: `brand`, пункты, `footer` | ориентир (landmark) «Navigation»            |
| `a[k-sidenav-item]` | директива: класс `k-sidenav-item`, иконка, текст, `k-count`           | `aria-current` от приложения; видимый фокус |
| `<k-sidenav-group>` | подпись группы + список                                               | `role="group"` + `aria-labelledby`          |
| счётчик             | `<span class="k-count k-num">`                                        | читается вместе с названием пункта          |

**Шаги, каждый — коммит с тестами (сначала красный):**

1. **UI-4a.** Компоненты и стили 1:1 по `components.css`. Тесты на роли, `aria-current` и
   клавиатуру (Tab по ссылкам). Stories: обычная, активный пункт, счётчики, группа, тёмная
   тема; axe в обеих темах.
2. **UI-4b.** Мобильная панель (drawer): открыть, закрыть по Escape, фокус внутри панели,
   после закрытия возврат на кнопку. **Нужен выбор** (вопрос 1).

## 8a · каркас SignFlow

1. **8a-1, раскладка.** `ShellComponent` для маршрутов после входа:
   - SideNav слева, шапка, `<main>`;
   - ссылка «Zum Inhalt springen» (переход к содержимому);
   - после перехода фокус ставится на `h1` страницы.
   - Профиль внизу: аватар, e-mail, «Abmelden» (сейчас кнопка выхода на `home`).
   - Тексты в de/en/ru.
2. **8a-2, тема.** По умолчанию берётся из `prefers-color-scheme`. Переключатель «System /
   Hell / Dunkel» сохраняет выбор в `localStorage`, тема ставится атрибутом `data-theme` на
   `<html>`. Тёмные токены уже есть. Выбор показывается до первой отрисовки, без вспышки
   светлой темы.
3. **8a-3, язык в каркасе.** Используется существующий `sf-language-switch`.
4. **8a-4, мобильный режим.** Кнопка-«бургер» в шапке открывает drawer из UI-4b.
5. **e2e.** После входа виден каркас. Навигация с клавиатуры. Пункт активен на своей
   странице. axe в светлой и тёмной теме. Мобильная ширина: drawer открывается и
   закрывается.

## Вопросы владельцу

1. **Drawer.** Подключить `@angular/cdk` (Overlay, FocusTrap), как в спецификации, — новая
   зависимость, нужен ADR? Или нативный `<dialog>`: без зависимости, ловушка фокуса и
   Escape встроены. Рекомендую `<dialog>`, а CDK взять, когда понадобится UI-3 Dialog или
   DropdownMenu.
2. **Пункты меню в v1.** Страниц пока нет, кроме стартовой. Варианты:
   - (а) показывать только пункты с готовыми страницами (сейчас Übersicht) и добавлять
     остальные вместе с их задачами;
   - (б) все пункты из макета, без страниц — пометка «geplant» без ссылки, как у Vorlagen.

   Рекомендую (а): нет кнопок, которые не работают.

3. **Где переключатели языка и темы?** В макетах их нет. Рекомендую в шапке справа, рядом
   с местом для колокольчика. Или в меню профиля, но DropdownMenu ещё не сделан.
4. **Шапка в 8a:** поиск, «Neuer Umlauf» и колокольчик принадлежат своим задачам. Рекомендую
   в 8a их не показывать.
5. **Имя в профиле.** В таблице `users` есть только e-mail. Аватар и подпись строить по
   e-mail, или в 8a добавить поле «имя» (это задача API и миграция)?
6. **«Verwaltung»** — только для администратора. Флаг администратора появится в задаче 9.
   До неё группу не показывать?
