# План задачи 003: токены Kontur в libs/ui (генератор из tokens.json)

> Нумерация: журнал 002 занят фиксом CI, поэтому эта задача получает номер **003**
> (`docs/plans/003-design-tokens.md`, `docs/journal/003-design-tokens.md`).

## Контекст (зачем)

Сейчас приложения рисуются браузерными стилями по умолчанию: шрифт Times, белый фон.
Дизайн-система Kontur описана в `docs/design/tokens.json` (v2). По
`docs/design/README.md` из этого файла нужно **сгенерировать** CSS, совпадающий с
эталоном `docs/design/tokens.css` 1:1. Цвета руками не переписываем.

Результат задачи:

- в `libs/ui` есть сгенерированный `tokens.css` со шрифтами;
- SignFlow, Belegscan и Storybook используют токены: фон `--bg-page`, шрифт IBM Plex;
- CI падает, если CSS устарел относительно JSON.

**Твои решения:**

- генератор — свой скрипт;
- выбор фиксируется в ADR (Style Dictionary отклонён, указано условие пересмотра);
- генератор — Nx-цель с inputs/outputs и кэшем;
- сгенерированный CSS коммитим, а CI проверяет его актуальность;
- golden-тест пишется **первым**, до генератора.

**Что уже есть в tokens.json v2:**

- `color.tokens`: 24 токена, значения `{light, dark}`, `focus-ring` ссылается на `{brand}`;
- `shadow.tokens`: `{light, dark}`;
- `spacing`, `radius`, `size`: плоские значения;
- `type.families`: шрифтовые стеки для sans и mono;
- `type.groups[].styles[]`: `fontSize`, `lineHeight`, `fontWeight`, а также необязательные `letterSpacing` и `fontVariantNumeric`;
- `type.fonts` (latin) и `type.fontSubsets.files` (cyrillic) + `unicodeRanges`.

**Порядок блоков в эталоне `tokens.css`:**

1. `@font-face` × 10 в порядке latin → cyrillic по каждой паре семейство/начертание;
2. `:root, [data-theme="light"]` — цвета и тени;
3. `[data-theme="dark"]` — цвета и тени;
4. `:root` — spacing, radius, size и `--font-sans`/`--font-mono`;
5. классы `.h1` … `.mono-sm`.

## Шаги и коммиты

### Коммит 1 · `docs(design): update Kontur snapshot to tokens v2`

Твои изменения в `docs/design/tokens.json` и `docs/design/README.md` коммичу как есть, отдельным коммитом. Это обновление снапшота, а не мой код.

### Коммит 2 · `docs(adr): ADR-0002 design tokens generated by own script`

`docs/adr/0002-design-tokens-generator.md` (MADR):

- **Решение:** собственный генератор на TypeScript, около 100 строк, проверяется golden-тестом против `docs/design/tokens.css`.
- **Отклонён Style Dictionary.** У нашего `tokens.json` свой формат (списки, расширения `fontSubsets` и `fontVariantNumeric`). Пришлось бы писать конвертер и кастомные форматы для тем, `@font-face` и классов.
- **Условие пересмотра:** появятся другие платформы (iOS/Android) или несколько брендов.
- **Сгенерированный CSS коммитится.** Ревьюер видит итоговый CSS в PR, а CI проверяет, что CSS не отстал от JSON.

Обновлю оглавление `docs/adr/README.md`.

### Коммит 3 · `feat(tokens): generate Kontur CSS from tokens.json (golden-tested)`

Новый Nx-проект **`tools/tokens`** (имя `tokens`, теги `scope:shared,type:util`). Это инструмент сборки, а не код приложения, поэтому он живёт в `tools/`.

**Порядок работы (test first):**

1. **Сначала golden-тест** `tools/tokens/src/generate-tokens.spec.ts`. Он читает `docs/design/tokens.json` и `docs/design/tokens.css`, затем:
   - разбирает эталон и результат генератора **postcss**. Это настоящий CSS-парсер, уже есть в devDependencies;
   - сравнивает **правило в правило**: тип правила, селектор или `@`-правило, список пар «свойство: значение» с нормализованными пробелами;
   - отдельно и наглядно проверяет: 10 `@font-face` (5 latin + 5 cyrillic, у каждого `unicode-range` своего сабсета); все custom properties обеих тем (24 цвета + 2 тени, в светлой и тёмной); все 10 классов стилей, включая `letter-spacing` у `.label` и `tabular-nums` у `.mono`/`.mono-sm`.
2. Запускаю тест и показываю тебе, что он **красный**: функции генератора ещё нет.
3. **Генератор** `tools/tokens/src/generate-tokens.ts` — чистая функция `generateTokensCss(tokens): string`, без файловой системы. Она:
   - собирает `@font-face`: для каждой записи в `type.fonts` сначала сама запись, затем подходящие файлы из `fontSubsets.files` с тем же семейством, весом и стилем; `unicode-range` берётся из `fontSubsets.unicodeRanges[subset]`;
   - собирает темы: из `color.tokens` и `shadow.tokens` по `color.themes` (`light` → `:root, [data-theme="light"]`, `dark` → `[data-theme="dark"]`); ссылка вида `{brand}` превращается в `var(--brand)`;
   - собирает блок `:root` из `spacing`, `radius`, `size` и `type.families`;
   - собирает классы: `.<name> { font: <weight> <size>/<lineHeight> var(--font-<family>); }`, а при наличии добавляет `letter-spacing` и `font-variant-numeric`;
   - описывает типы `tokens.json` TypeScript-интерфейсами, без `any`.
4. Тест **зелёный**.
5. **CLI** `tools/tokens/src/cli.ts`, запускается обычным `node` (Node 24 сам понимает TypeScript без компиляции, только синтаксис типов):
   - `generate`: пишет `libs/ui/src/styles/tokens.css` и копирует 10 woff2 из `docs/design/fonts/` в `libs/ui/src/styles/fonts/`. Шрифты копируются по списку из JSON, лишних файлов не будет;
   - `--check`: генерирует в память и сравнивает с закоммиченным CSS и шрифтами. При расхождении печатает `tokens.css is out of date — run: pnpm nx run tokens:generate` и выходит с кодом 1.
   - **`tools/tokens/tsconfig.json`** с `"erasableSyntaxOnly": true`. Node удаляет типы, но не умеет выполнять `enum`, `namespace` и parameter properties. Эта опция заставляет TypeScript ловить такой синтаксис при typecheck и lint, а не при запуске. В журнале это объясняется.
6. **`tools/tokens/project.json`**, цели явные, без магии плагинов:
   - `generate`: `cache: true`; inputs — `tokens.json`, шрифты в `docs/design/fonts/**` и `{projectRoot}/src/**`; outputs — `libs/ui/src/styles/tokens.css` и `libs/ui/src/styles/fonts`;
   - `check`: `cache: true`; те же inputs плюс закоммиченный CSS и шрифты;
   - `test`: `vitest run` в Node-окружении (свой маленький `vitest.config.mts`); Vitest уже стоит;
   - `lint`: добавит плагин ESLint.

Коммит включает тест, генератор, CLI, конфиги и сгенерированный CSS со шрифтами. Красный тест из пункта 2 отдельным коммитом не делаю: красный коммит на `main` ломал бы историю для `git bisect`. Красный прогон покажу в чате и опишу в журнале.

### Коммит 4 · `feat(ui): apply Kontur tokens and fonts in apps and Storybook`

- **`libs/ui/src/styles/base.css`**, написан руками. Только `body { margin: 0; background-color: var(--bg-page); color: var(--text-primary); }`. Только `var()`, ни одного литерального значения.
- **`index.html` обоих приложений:** `<body class="body">`. Шрифт берётся из сгенерированного стиля `.body` (14/20 Plex Sans), а не дублируется руками.
- **`project.json` signflow, belegscan, ui-storybook:** в `styles` добавляю `libs/ui/src/styles/tokens.css` и `base.css`. Бандлер Angular (esbuild) сам найдёт `url("fonts/…woff2")` и положит шрифты в сборку с хэшем в имени.
- **`libs/ui/ng-package.json`:** добавляю `assets` со `src/styles/**`, чтобы npm-пакет содержал CSS и шрифты. Проверю в `dist/libs/ui`.
- **E2E (сначала тест, потом подключение стилей)**, в обоих smoke-спеках:
  - фон `body` равен `rgb(247, 248, 250)`, то есть `--bg-page` светлой темы из tokens.json;
  - `font-family` у `body` начинается с `"IBM Plex Sans"`;
  - в `document.fonts` зарегистрировано 10 начертаний;
  - `document.fonts.load('400 14px "IBM Plex Sans"', 'Ä')` и `…('Ж')` реально загружают файлы. Так проверяем, что latin- и cyrillic-шрифты доходят до браузера;
  - axe по-прежнему без нарушений.

### Коммит 5 · `ci: fail when generated tokens.css is out of date`

В `ci.yml` добавляю шаг **«Design tokens up to date»**: `pnpm nx run tokens:check`. Он запускается всегда, независимо от affected. `tokens.json` лежит вне проектов Nx, поэтому `affected` его изменения может не заметить, а сама проверка дешёвая.
