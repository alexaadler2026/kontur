# План задачи 012: Badge и Avatar / AvatarStack

Одобрен 2026-11-15. Вторая половина исходного плана — 013: KonturIntl и Tag.

## Решения (с ответами владельца)

1. **Разбивка** на 012 (Badge, Avatar, AvatarStack — только отображение) и 013 (KonturIntl + Tag) — да.
2. **Дизайн v4.2** — владелец добавил:
   - `.k-tag-x` в общее правило фокуса;
   - класс `.k-avatar--more` вместо inline-стиля.

   Закоммичено первым: `docs(design): tag remove focus ring and avatar more class`. Оба правила перенесены дословно.

3. **Avatar** — `role="img"`, `aria-label` = полное имя. **Стек** — один `role="img"` с подписью от приложения, кружки внутри скрыты от скринридера (записано и в Avatar.md).
4. Для 013 уже решено:
   - имя крестика Tag = `aria-labelledby` «кнопка + текст тега»;
   - фокус после удаления переводит тот, кто использует тег.

## Коммиты

1. `docs(design): tag remove focus ring and avatar more class`
2. `feat(ui): add k-badge, k-avatar and k-avatar-stack`
3. `docs(journal): add entry 012 badge avatar` — этот план и журнал.

## Отклонения при выполнении

- **Вся секция «Badge / Tag / Avatar» перенесена сразу**, вместе с правилами `.k-tag`: по ADR-0003 одна секция эталона — один файл. Компонент `k-tag` появится в 013.
- **Кружки внутри стека** — простые `<span class="k-avatar" aria-hidden="true">`, а не вложенные `<k-avatar>`. Так внутри одной картинки (`role="img"`) нет других картинок с собственными именами.
- **Регистр инициалов** — `toUpperCase()`, без учёта локали. Для имён на de/en/ru результат тот же. Особые случаи вроде турецкой «i» в продукте не встречаются.
- **e2e не был красным до реализации.** Вместо этого есть записанная мутация, как разрешает обновлённое правило CLAUDE.md: без поворота ромба и без `.k-avatar--more` оба e2e-теста упали.
- **В моём e2e был баг:** `getByRole('img', { name: 'Anna Berger' })` ищет подстроку и находил ещё и стек, в чьей подписи тоже есть «Anna Berger». Исправлено на `exact: true`.
